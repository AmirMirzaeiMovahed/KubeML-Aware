# ممیزی به‌روز ادعاهای مقاله و وضعیت بازتولید

تاریخ ممیزی: ۲۰۲۶-۰۸-۰۸

مبنای مقایسه: Abdelshaheed and Ashour، مقالهٔ *Intelligent Scheduling of
AI Tasks in Kubernetes* (2025)، فایل مرجع نسخه‌دار
`experiments/article_reference.yaml` و شواهد استقرار فرانسه.

## نتیجهٔ صریح

پیاده‌سازی از نظر **قرارداد الگوریتم، workload، برنامهٔ آزمایش و تحلیل آماری**
به مقاله نزدیک و آمادهٔ بازتولید است، اما از نظر **خروجی عددی مقاله هنوز چیزی
بازتولید نشده است**. ماتریس قفل‌شدهٔ ۷۰ اجرای مقاله روی محیط اختصاصی اجرا نشده؛
بنابراین وضعیت درست «آماده برای reproduction» است، نه «نتایج مقاله تأیید شد».

برای جلوگیری از مخلوط‌شدن آمادگی کد با شواهد تجربی، وضعیت در چهار محور گزارش
می‌شود:

| محور | وضعیت قابل دفاع |
|---|---|
| قرارداد اصلی الگوریتم | ۸/۸ جزء اصلی در سورس و تست‌ها پیاده‌سازی شده است |
| workload و پروتکل آزمایش | سناریوها، ۵ repetition، pacing، reversed و Plan دقیق ۷۰ اجرا قفل شده‌اند |
| اعتبارسنجی عملی فرانسه | production scheduling-gate و extension مربوط به inference با موفقیت smoke شده‌اند |
| بازتولید ادعاهای عددی مقاله | **۰/۹ ادعای اثر اندازه‌گیری شده**؛ نه رد شده و نه تأیید شده |

هر درصد کلی مانند «۹۰٪ تطابق» بدون تعریف مخرج گمراه‌کننده است. نزدیک‌ترین بیان
دقیق این است: **تطابق طراحی بالا، آمادگی آزمایش بالا، شواهد عددی هنوز صفر**.

## ادعاهای روش و تطابق پیاده‌سازی

| ادعای مقاله | وضعیت پروژه | ارزیابی |
|---|---|---|
| رتبه‌بندی ML-aware پیش از اجرا | `scheduler/rank.py` و Burst collector | پیاده‌سازی و تست شده |
| شش ویژگی `T,R,M,G,C,P` | Generator، Trainer، Ranker و schema مشترک | پیاده‌سازی و تست شده |
| کمتر بودن `T,M,G,P` و بیشتر بودن `R,C` مطلوب است | جهت Min-Max صریح و تست‌شده | تطابق مستقیم |
| Min-Max در سطح هر Burst | بردارها و حالت مقادیر برابر تست شده‌اند | تطابق مستقیم |
| ترتیب نزولی Rank و Reversed ablation | tie-break قطعی و مسیر `--reverse` | پیاده‌سازی و تست شده |
| Manual Pod Binding روی scheduler مستقل | reproduction scheduler و RBAC آماده‌اند | کد آماده؛ اجرای زندهٔ مقاله pending |
| pacing و تأیید `EXECUTION_STARTED` | حالت‌های ۰، ۱، ۲ و ۵ ثانیه و marker سخت‌گیرانه | محلی تست شده؛ اجرای زندهٔ مقاله pending |
| پیچیدگی `O(N log N)` | محاسبهٔ خطی feature/rank و sort | با ساختار پیاده‌سازی سازگار است |
| چهار گروه synthetic workload | light، heavy، I/O-intensive و slow-converging | پیاده‌سازی شده؛ پارامترهای کامل مقاله منتشر نشده‌اند |
| CPU-only و single-node | reproduction profile تک‌گره‌ای و BLAS تک‌نخی | آماده؛ روی محیط اختصاصی مقاله اجرا نشده |

پروفایل production که اکنون در فرانسه فعال است scheduling gate را به ترتیب
Rank حذف می‌کند و Binding نهایی را به `default-scheduler` می‌سپارد. این روش برای
Kubernetes واقعی امن‌تر است، ولی با Manual Binding مقاله یکسان و از نظر عددی
قابل مقایسه نیست.

## چیزی که واقعاً در فرانسه اثبات شده است

روی سرور فرانسه این موارد به‌صورت زنده پذیرفته شده‌اند:

- K3s `v1.36.2+k3s1` تک‌نودی Ready است.
- controller پروفایل production یک Burst دو Pod مربوط به inference را با
  Rankهای `0.95` و `0.05` به ترتیب درست release کرده است.
- هر دو Pod marker شروع معتبر داده، کامل شده و state نسخهٔ 3 روی PVC ثبت شده است.
- Knative Service و Revision دوم Ready هستند و scale-to-zero و cold-start واقعی
  smoke شده‌اند.
- ۱۴۵ تست، build نسخهٔ `0.2.1`، Helm lint/render و server-side dry-run پاس شده‌اند.

این شواهد نشان می‌دهند طراحی روی Kubernetes واقعی کار می‌کند؛ اما چون workload
آموزش، Manual Binding، baselineهای default/custom/reversed و ۵ repetition مقاله
اجرا نشده‌اند، شاهد بازتولید عددهای بالا نیستند.

## چرا فرانسهٔ فعلی محیط article-exact نیست

| الزام مقاله/پروفایل | فرانسهٔ فعلی |
|---|---|
| Minikube با Docker driver | K3s با containerd |
| ۴ CPU و ۸ GiB | ۴ CPU و حدود ۷.۶ GiB؛ از نظر ظرفیت نزدیک |
| node تمیز و اختصاصی | ۲۲ Pod فعال شامل VPN، monitoring، Knative و ingress |
| بدون بار مزاحم | هنگام ممیزی 28% CPU و 58% RAM مصرف می‌شد |
| Manual Binding reproduction profile | production scheduling-gate profile |

اجرای ۷۰ run روی همین node، هم اعتبار علمی را خراب می‌کند و هم می‌تواند سرویس
VPN را تحت فشار بگذارد. مسیر درست یک VM/Node موقت و اختصاصی با Minikube Docker،
۴ CPU و ۸ GiB است؛ سپس Plan قفل‌شدهٔ `article-70.json` بدون اجرای هم‌زمان دیگری
اجرا و با Analyzer سخت‌گیرانه تحلیل می‌شود.

## محدودیت‌هایی که مقاله اجازهٔ بازسازی دقیقشان را نمی‌دهد

مقاله repetitionهای خام، seedها، دامنه و نسبت دقیق چهار category، روش calibration
وزن‌ها، تبدیل عددی half-load، ثابت‌های workload، نسخه‌های نرم‌افزار و روش دقیق
percentile را کامل منتشر نکرده است. انتخاب‌های پروژه برای این موارد فرض‌های
نسخه‌دار بازتولید هستند و نباید به نویسندگان نسبت داده شوند.
